## §2 KDD-060 — Canonical quorum selection and the quorum-membership predicate

**KDD-060 (2026-06-13). The PTXDKG quorum at a formation is exactly
`GetListForBlock(formation block).CalculateQuorum(11, quorum_hash)` — one
function, raw modifier, for both formation and validation. CheckPTXDKGTx
verifies committer membership in THIS set, not mere DGM registration.
Amends KDD-059.**

### 2.1 The gap being closed

KDD-059's predicate "each committer was a registered GM at formation_height" is strictly weaker than quorum membership. The DGM registry at a height is a superset of the score-selected top-11 (`CalculateQuorum`, deterministicgms.cpp:224–243, scores ALL valid confirmed GMs via `ForEachGM(true, …)` then truncates to `maxSize`). Under the bare-registration predicate, any ≥ t registered-but-unselected GMs (rank 12+) could co-sign mutually-agreeing premit attestations and inject a PTXDKG that passes every check — enshrining an attacker-chosen group_pk for a formation they were never part of. This breaks the KDD-058 determinism coupling directly: block-inject is I2-safe only because `CheckPTXDKGTx` rejects wrong results.

### 2.2 The canonical-selection contract

For formation anchor block B (identified by `quorum_hash = B.GetBlockHash()`):

```
quorum(B) := deterministicGMManager->GetListForBlock(pindex_B)
                 .CalculateQuorum(11, B.GetBlockHash())
```

- **One implementation.** Both ceremony formation (W2) and consensus validation (W1.3) call this function. No reimplementation, no "equivalent" scorer, ever.
- **Raw modifier.** `quorum_hash` is consumed as the raw 32-byte uint256 modifier. PTX MUST NOT use `GetAllQuorumMembers` (deterministicgms.cpp:991–997), which wraps the modifier as `SerializeHash(pair(llmqType, blockHash))` — a different value producing a different quorum.
- **Ordering and share_index.** `CalculateQuorum` output is descending by score with a deterministic `collateralOutpoint <` tie-break under `std::sort` (deterministicgms.cpp:224–244; collaterals are unique, so total order). This descending order IS the KDD-052 score order. `share_index := position + 1` in this output (position 0 → share_index 1).
- **Score formula (inherited, now sole):** per-GM score = `SHA256( confirmedHashWithProRegTxHash[32] || modifier[32] )` where `confirmedHashWithProRegTxHash = SHA256(proTxHash[32] || confirmedHash[32])` (deterministicgms.cpp:260–266; deterministicgms.h:113–120). Null-confirmedHash GMs are excluded by `CalculateScores` itself (deterministicgms.cpp:250).

### 2.3 Scorer retirement (consequence, not optional cleanup)

`PTX_DKG_ComputeMemberScore` (ptx_dkg.cpp:107–118) and `PTX_DKG_SortMembers` (ptx_dkg.cpp:121–145) are RETIRED — removed, not quarantined. Recon proof this is required for correctness, not just hygiene:

- `SortMembers` uses `std::stable_sort` with **no tie-break**; `CalculateQuorum` uses `std::sort` with the `collateralOutpoint` tie-break. The two are byte-equivalent **only on tie-free inputs** — under a score tie at the 11/12 boundary they select different quorums and assign different share_index values (D13/D14).
- Score-formula parity (`ComputeMemberScore` ≡ `CalculateScores` inner loop) holds iff fed the cached `confirmedHashWithProRegTxHash` (D14) — so existing phase0 determinism/sensitivity tests can migrate to `CalculateQuorum`-derived expectations rather than being deleted blind.
- Retirement inventory (E15): production callers = exactly one (`InitSession` ptx_dkg.cpp:156), which is itself production-uncalled. Test callers: ptx_dkg_phase0_tests.cpp T0-1/2/4/5/6 (lines 163–164, 183–184, 217–245, 262). Comments naming SortMembers: ptx_dkg.h:75, ptx_dkg.h:310 — updated with the rebase.

### 2.4 KDD-059 relationship

KDD-059's verified-list clause "Each committer was a registered GM at formation_height" is **superseded** by "Each committer ∈ quorum(B)". All other KDD-059 content stands (attestation-counting semantics, accountability boundary, ODC-027/028 deferrals, member_node_ids cosmetic, bifurcation/cs_main consequence). §19 gets an addendum line pointing here; no in-place edit.

## §3 Consensus validation — CheckPTXDKGTx

### 3.1 Bifurcation and locking

- Insertion point (C12): the contextual block begins after the existing `ptxdkg-insufficient-premits` check and before `return true;` (specialtx_validation.cpp:610–652). The null path (`pindexPrev == nullptr`) is the bae1dcf structural body, **unchanged**: payload deserialize, group_pk G1 decompress, member_node_ids count (non-empty, ≤ 11), premit count ≥ t=6, per-premit `sig.IsValid()` non-null check.
- The structural checks run unconditionally (both paths); the contextual sequence (§3.2) runs only when `pindexPrev != nullptr`.
- Locking: `CheckPTXDKGTx` gains `EXCLUSIVE_LOCKS_REQUIRED(cs_main)` in the header and `AssertLockHeld(cs_main)` at entry — unconditional, mirroring `CheckLLMQCommitmentTx` (specialtx_validation.cpp:589/591). Tests calling it (including null-path tests) take `LOCK(cs_main)`. `GetListForBlock` holds its own internal `cs` (deterministicgms.cpp:852), not cs_main; cs_main is required for `LookupBlockIndex`/chain access and to match the CheckSpecialTx call-site contract (AssertLockHeld at specialtx_validation.cpp:707).
- The W1.2 entry `LogPrintf` warning ("structural check only") is removed — no longer true.

### 3.2 Contextual check sequence (in order; first failure rejects)

**Strictness rationale (V8):** the LLMQ template rejects on any inconsistent claimed signer (bits-beyond-keys check, quorums_commitment.cpp:92–99) rather than counting survivors. The PTXDKG builder controls the payload; an honest builder includes only valid premits. Count-the-survivors semantics would let a builder pad garbage entries that honest validators must waste BLS verifies on.

### 3.3 GetListForBlock throw path

`GetListForBlock` throws `std::runtime_error` when the height has no snapshot/diff and is post-activation ("Possible corrupt database", deterministicgms.cpp:896–899). After V3, the anchor block is guaranteed in the active chain at connect time, so a missing list is local DB corruption. **The throw propagates** — no try/catch. This is the inherited template behavior (the LLMQ path calls the same machinery uncaught); catching it would convert local corruption into a consensus reject, which is wrong in both directions.

### 3.4 Distinctness, and the key↔inner binding (new finding)

The serializer's `std::map` deserialization hint-inserts and silently drops duplicate keys (serialize.h:1222–1240); the post-insert map size is what the ≥ t check counts — so duplicate *keys* cannot inflate the count. **But map-key distinctness alone is insufficient**: `PTXDKGPhase4Msg` carries its own `proTxHash` field (it is in the sign-hash preimage, ptx_dkg.cpp:972–986). Without V7a, one member's valid premit could be inserted under several different map keys — distinct keys, identical inner attestation — and each copy's signature verifies (the sig covers the *inner* proTxHash, not the key). V7a pins key == attested identity; with it, ≥ t distinct keys ⇒ ≥ t distinct attesting members. This is the PTX analogue of LLMQ's bitset-position-as-identity (quorums_commitment.h:32–46): there, the position can't be forged; here, the binding check makes the key unforgeable.

This finding sharpens KDD-059's "distinct" clause: distinctness is key-enforced **conditional on V7a**, which the W1.2 structural path does not perform. Record in the KDD-060 text.

> **Corrected 2026-07-01 (C-4 — reconciles to the shipped V7f design; design-doc §20.4 carries the same correction).** The paragraph above assumed V7f resolves the operator key from the *inner* proTxHash. The shipped validator (decision-4) reads it off the **map key** (V6 `quorum_map`), and the C-2 falsification cycle proved the "one premit duplicated under N keys" inflation is **NOT caught by V7a** under this design — **V7g backstops it** (the duplicated sig does not verify under another member's operator key; reject `ptxdkg-bad-premit-sig`). ≥ t-distinct-attestation soundness therefore rests on **map-key dedup + V7b (membership) + V7g (sig verify) + V7d/e (agreement)**. V7a's isolating role is the **inner-mislabel case** ("member K signs with inner P ≠ K") — it is the sole catcher of that, and is kept as a cheap, spec-mandated binding (defense-in-depth). No behaviour change; the "load-bearing for distinctness/inflation" framing is corrected, not the code.

### 3.5 Explicitly NOT verified (restated from KDD-059)

- Share-correctness / honest Feldman VSS (ODC-027 — vvecs not in payload; only the irreversible vvec_hash).
- Threshold-recoverability (ODC-028 — no recovered threshold sig; the premits ARE the threshold evidence).
- `member_node_ids` content/ordering — cosmetic; consensus weight limited to the W1.2 structural count check. The contextual path adds NO node_id checks.
- Non-canonical map encodings (dup/disordered keys silently normalized by the inherited deserializer) — inherited behavior for every map-bearing payload codebase-wide; W1.3 operates on the post-deserialization map and does not fix the serializer.

## §4 Block-inject wiring (KDD-058 mechanisms — lands WITH §3, never before)

Sequencing invariant: the wiring commit must not precede the validation commit on the branch (KDD-058/059 coupling — injection is I2-safe only once validation rejects bad results). Single commit or validation-first.

1. **tx_verify exemption:** `IsPTXDKGTx()` exempted from empty-vin/vout rejection in consensus/tx_verify.cpp, parallel to `IsQuorumCommitmentTx()` (tx_verify.cpp:59,63). Without it, PTXDKG dies `bad-txns-vin-empty` before `CheckSpecialTx` runs.
2. **Mempool rejection:** PTXDKG rejected from `AcceptToMemoryPool`, parallel to llmqcomm/ptxcoalesce/ptxpayout (validation.cpp:386–395).
3. **Injection hook:** `GetMinablePTXDKGTx()` in the CreateNewBlock post-mempool injection block (blockassembler.cpp:200–273), mirroring `GetMinableCommitmentTx`. Source: a small pending-PTXDKG slot (own lock, not cs_main) populated by `PTX_DKG_ClosePhase5` via the existing construct-only `PTX_DKG_BuildPTXDKGTx`; cleared on inclusion-confirmed or supersession.
4. **One PTXDKG per block:** block-level rule — at most one PTXDKG tx in a block (cheap structural check in the block special-tx processing path). Cross-block per-formation uniqueness is ODC-030 (§6).

**Status (C6/C7, 2026-07-04):** items 1 (tx_verify exemption) and 2 (mempool rejection, = F-5) are shipped and falsification-proven; item 3 (injection hook) drives the C6 rows; item 4's *invocation* (C3-INVOCATION — two valid PTXDKGs → `ptxdkg-duplicate` through the real path) is **NOT unit-covered** and **bound to W2.2** (needs a connect-valid payload = datadir-v2). Full closure state in §8.1.

## §5 Ceremony-side changes (the KDD-060 rebase)

### 5.1 PTX_DKG_InitSession — new contract

**Contract:** the caller supplies `members` in **CalculateQuorum output order** (the canonical descending-score order). InitSession preserves that order; it never re-sorts.

Body changes (current body at ptx_dkg.cpp:151–175):
- **Remove** the `PTX_DKG_SortMembers` call (line 156) — under the new contract the re-sort is redundant on tie-free inputs and actively wrong under a tie (stable_sort-no-tiebreak vs sort-with-collateral-tiebreak, E17 finding 1).
- **Keep / move in:** size == 11 check (line 159); per-member `confirmedHash` non-null fail-fast (was inside SortMembers — retained as a cheap precondition assert even though `CalculateScores` already excludes nulls); **add** a distinct-proTxHash check (E17: currently nothing enforces distinctness in InitSession).
- **share_index assignment stays in InitSession:** `members[i].share_index = i + 1` over the caller-supplied order — assignment formula unchanged, ordering source changed. Single write site preserved.
- my_idx scan unchanged.

### 5.2 New thin helper (the only new selection code)

`PTX_DKG_BuildMemberVectorFromList(const CDeterministicGMList& list, const uint256& formation_block_hash) → std::vector<PTXDKGMember>`: maps each `CDeterministicGMCPtr` → `PTXDKGMember` (proTxHash, node_id, chiabls pubKeyOperator). A wrapper around the canonical function — not a scorer. W2 formation calls it.

> **Reconciled 2026-07-01 (C-4 — shipped at C-1 `d52106b`).** The selection itself is the extracted shared core `PTX_DKG_SelectQuorumFromList(const CDeterministicGMList&, const uint256&) → std::vector<CDeterministicGMCPtr>` (filter by `PTX_DKG_IsGMPTXEligible`, then `CalculateQuorum(11, quorum_hash)`). `BuildMemberVectorFromList` **wraps** it (adding the `PTXDKGMember` mapping). ## §6 ODC-030 (new) — PTXDKG acceptance window and per-formation uniqueness

**Open.** Two lifecycle-bound acceptance rules deliberately deferred to W2:

1. **Staleness bound:** LLMQ enforces max-age via `cacheDkgInterval` (specialtx_validation.cpp:565–567); PTX has no interval analog and no formation cadence yet. Inventing a consensus constant before W2 defines rotation cadence is guessing. W1.3 ships V1–V3 (existence, height-consistency, ancestor) with **no max-age bound**.
2. **Cross-block per-formation uniqueness:** "one accepted PTXDKG per formation absent rotation/disband" needs a chain-state index (quorum_hash → accepted txid) maintained in Connect/DisconnectBlock, and its legality condition is exactly W2's rotation semantics. Interim risk is bounded: a *conflicting* second group_pk for the same formation requires ≥ t members signing both — outside the KDD-059 trust boundary; a *duplicate* identical PTXDKG is chain bloat, mitigated by the one-per-block rule (§4.4) and the §C1 node-side guard (§5.5).

**Resolve with:** W2 lifecycle design. Both clauses may split into separate ODCs at registration if preferred.
